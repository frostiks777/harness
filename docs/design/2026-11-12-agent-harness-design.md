# AI-харнесс для OpenCode — дизайн дистрибуции

- **Дата:** 2026-11-12
- **Статус:** секции 1–5 согласованы в чате; документ ожидает ревью владельца.
- **Источник истины:** `C:\My_projects_GIT\1pg_gall` (далее — «источник»). Харнесс целиком
  однажды уже переносился из `ai-for-developers-project-386`, процедура повторяется.
- **Целевой репозиторий:** `agent-harness` (публичный, GitHub-аккаунт владельца).

## 1. Цель

Один публичный репозиторий, содержащий **переиспользуемое ядро** AI-харнесса
(инструкции агенту, скиллы, процессные документы, конфиг OpenCode) и `INSTALL.md` —
задание агенту, по которому он в целевом проекте **сам накатывает харнесс на себя**:
копирует ядро, задаёт владельцу обязательные вопросы, адаптирует плейсхолдеры,
верифицирует результат и отчитывается с доказательствами.

Сценарий владельца: открыть репозиторий харнесса в целевом проекте → сказать агенту
«прочитай INSTALL.md и накати» → ответить на 3 вопроса → получить отчёт PASS/FAIL.

## 2. Не-цели

- **Не дистрибуция проекта «Photo Gallery»**: `MEMORY.md`, `CONTEXT.md`, `docs/adr/`,
  деплой, nginx, release-please, `ci.yml`/`deploy.yml`, `.gitleaks.toml` — не входят.
- **Не скрипт-установщик**: установку выполняет агент по инструкции (выбор владельца).
- **Не замена апстрим-каталогам**: 38 скиллов остаются с происхождением
  `mattpocock/skills`; `skills-lock.json` сохраняется как доказательство происхождения.
- **Не универсальный харнесс для всех агентов**: ядро — OpenCode; Claude Code, Cursor,
  GitHub Actions, Telegram — опциональные адаптеры.
- **Не предполагает стек целевого проекта**: проект может быть на Java, Python, Go, вебе
  или вообще не код. Ни одна команда/конвенция источника не становится данностью.

## 3. Структура репозитория (утверждена)

```

├── README.md               # для людей: что это, из чего собрано, быстрый старт
├── INSTALL.md              # для агента: задание «накати харнесс на целевой проект»
├── AGENTS.md               # шаблон ядра инструкций — без специфики проекта
├── opencode.jsonc          # ядро-конфиг OpenCode (модель, explore-агент; без MCP)
├── skills-lock.json        # происхождение 38 апстрим-скиллов
├── LICENSE                 # MIT (собственный контент)

├── scripts/
│   └── notify.ps1          # Windows-тост, UTF-8 с BOM, нейтральный AppId
├── .agents/
│   ├── skills/             # 84 скилла (86 минус apply-design, apply-design-v2)
│   └── shared/
│       └── checks.md       # шаблон чек-чейна с плейсхолдерами команд
├── docs/
│   ├── agents/             # issue-tracker.md, triage-labels.md, code-comments.md
│   └── updating.md         # как обновлять харнесс из источника

    └── telegram/           # telegram-bot/ (скрипты) + .opencode/plugins/telegram-autostart.js
```

**Dogfooding:** корневой `AGENTS.md` — одновременно инструкция для агентов, работающих
над самим харнессом, и шаблон, который копирует установочный агент. Репо-специфика
(процедура синхронизации с источником) живёт в `docs/updating.md`, чтобы не утекать
в целевые проекты.

**Исключено сознательно:**

| Что | Почему |
|---|---|
| `.agents/skills/apply-design`, `apply-design-v2` | курсовой проект, «do not apply here» (AGENTS.md источника) |
| `.claude/rules/security.md`, `.cursor/rules/00-security.mdc` | generic boilerplate из шаблона, не политика проекта |
| `docs/agents/domain.md` | глоссарий галереи |
| Next.js-блок из `AGENTS.md` | вшивается самим `next dev`, проект/стек-специфичен |
| shadcn MCP из `opencode.jsonc` | специфика фронтового стека галереи |
| `MEMORY.md`, `CONTEXT.md`, `docs/adr/` | проектная память, не переносится |
| telegram state (`.env`, `*.jsonl`, pid/lock) | личные данные владельца, gitignored навсегда |

## 4. Стек-нейтральность ядра

- `AGENTS.md`-шаблон не содержит названий языков, менеджеров пакетов, фреймворков и
  команд. Плейсхолдер-секции с HTML-комментариями `<!-- заполни -->`: «Описание проекта»,
  «Команды проверок» (ссылка на `checks.md`), «Layout & data flow», «Deployment»,
  «Known baseline», «UI-язык».
- `.agents/shared/checks.md` — шаблон: порядок «lint → typecheck → build → tests»,
  вместо команд — плейсхолдеры `«<команда линта проекта>»` и требование заполнить
  реальными командами.
- `opencode.jsonc` — только модель, `agents.explore` permissions и комментарий «как
  добавить MCP»; никаких MCP-серверов, привязанных к стеку.
- Процессные скиллы адаптируются: проектные упоминания источника заменяются
  нейтральными формулировками (`verify` — 13 упоминаний, `interview` — 5,
  `commit-push` — 5, `ponytail`/`tdd`/`process-inbox` — по 2, `plan` — 1).
  Перед копированием — прогон `grep` по всем 86 скиллам на маркеры
  `1pg|галере|photo|gallery|duckdns|ap-p-g|bun run|next dev|\.data`.

## 5. `INSTALL.md` — спецификация

Пишется как прямое задание агенту. Разделы:

1. **Роль и цель.** «Ты агент в проекте X. Накати харнесс, не потеряв уже настроенное».
2. **Предусловия.** OpenCode v2 (или адаптер), git; репозиторий харнесса доступен по URL
   **или** локальным путём.
3. **Шаг 0 — разведка целевого проекта.** Есть ли `AGENTS.md`/`CLAUDE.md`/`.agents/`/
   конфиги? Политика: **не перезаписывать, а интегрировать**; существующие инструкции
   владельца приоритетны; конфликты — в отчёт, не молчаливая замена.
4. **Шаг 1 — вопросы до установки** (обязательны, встроенный `question(...)`):
   - **Модель** для `opencode.jsonc` (по умолчанию предложить
     `opencode/mimo-v2.6-flash-free`, шаблон остаётся валидным).
   - **Telegram-мост** — ставить ли адаптер `telegram/` (нужны токен и chat id).
   - **GitHub Actions** — ставить ли адаптер `github-actions/` (потребует секретов
     `OPENROUTER_API_KEY` и переменной `OPENCODE_MODEL`).
   - **Claude/Cursor** — нужны ли адаптеры.
5. **Шаг 2 — копирование ядра** с сохранением dotfiles: `AGENTS.md`, `.agents/`,
   `opencode.jsonc`, `docs/agents/`, `scripts/notify.ps1`, `skills-lock.json`.
   **`LICENSE` харнесса не копируется** — это лицензия репозитория-источника, а не
   целевого проекта; копирование ложно перелицензировало бы проект.
   **`THIRD-PARTY-NOTICES.md` копируется обязательно** вместе со скиллами — MIT и
   Apache-2.0 требуют сохранения атрибуции в копиях.
6. **Шаг 3 — адаптация плейсхолдеров.** Заполнить секции AGENTS.md и `checks.md`,
   выключить неприменимые части (worktrees — опционально; Telegram — без адаптера).
7. **Шаг 4 — гигиена секретов.** Ни один `.env`/токен не копируется; `.gitignore`
   дополняется, если в нём нет `.env*`.
8. **Шаг 5 — верификация** по чек-листу §7; каждый пункт — с доказательством.
9. **Шаг 6 — отчёт.** Что скопировано, адаптировано, пропущено и почему; PASS/FAIL по
   каждому пункту верификации.
10. **Идемпотентность.** Повторный запуск обновляет файлы диффом к репозиторию харнесса;
    локальные правки владельца не затираются вслепую (показать дифф, спросить).

## 7. Верификация (чек-лист установочного агента)

1. **Файлы на месте**: ядро + выбранные адаптеры; `.agents/skills` = 84; лишнего нет.
2. **Плейсхолдеры закрыты**: `grep` по `<!-- заполни`/`{{` = 0 (кроме сознательно пустых).
3. **`opencode.jsonc` валиден**, модель — из ответа владельца.
4. **Скиллы видны OpenCode**: `skill`-инструмент находит процессный набор
   (`interview`, `plan`, `ponytail`, `tdd`, `verify`, `commit-push`); доказательство —
   фактический вызов/листинг. OpenCode читает `.agents/skills/` нативно (подтверждено
   сессией в источнике).
5. **`checks.md` реален**: каждая команда запущена, коды возврата в отчёте; незаполненное
   помечается «требует владельца», а не PASS.
6. **Секретов нет**: `grep` по `api[_-]?key|token|password|BEGIN.*PRIVATE KEY`; `.env`
   отсутствует и не закоммичен.
7. **Личных данных нет**: `grep` по известным маркерам (IP, домен, ник, SSH) = 0.
8. **Адаптеры только по согласию**: для `github-actions` — YAML валиден, README
   перечисляет секреты; если адаптер не выбран — файлов нет.
9. **Интеграция**: прежние инструкции владельца сохранены, дифф показан.
10. **Отчёт с доказательствами**: PASS/FAIL + вывод команд; любой FAIL блокирует «готово».
